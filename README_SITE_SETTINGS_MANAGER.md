# Ecobay: настройки сайта, отдельная статистика и роль руководителя

Патч подготовлен относительно актуального архива App_Data.zip, присланного после
применения всех предыдущих патчей. Внутри — только изменённые/новые исходники и эта инструкция.

## Установка

1. Сохраните копию текущего проекта и БД.
2. Распакуйте ZIP в корень проекта, заменив файлы с теми же путями.
3. Выполните `dotnet build` и проверьте на тестовом экземпляре.
4. Опубликуйте приложение, перезапустите пул/процесс и обновите страницу.
5. Войдите администратором. В Настройки сайта → Пользователи назначьте нужному
   сотруднику роль «Руководитель». Изменение роли завершает прежние сессии сотрудника.

НОВОЙ МИГРАЦИИ НЕТ. Новая роль хранится строкой Manager в существующем AdminUsers.Role;
длина и тип колонки не менялись. Статистика использует существующие Requests/PhoneClicks.
Ранее установленная миграция надёжных заявок/кликов должна оставаться применённой.
Существующим администраторам автоматически роль не меняется.

В среде подготовки патча нет .NET SDK и SQL Server: сборка и интеграционные тесты
не запускались. Статические проверки ссылок/прав и целостности архива выполнены.

## Меню

Дашборд / Заявки / Маршруты / Обращения / Статистика / Настройки сайта.
В настройках: Главная страница, Города, Цели, Пользователи (только Admin), Мой профиль.
Мобильный бургер сохранён; настройки на телефоне — компактная сетка кнопок с переносом.

## Роли

Admin — полный административный доступ вне зависимости от логина, включая удаление
заявок и управление ценами/ролями. Исключений для логина admin больше нет.
Сохраняются общие защитные ограничения: нельзя отключить себя, поменять себе роль/логин
через редактор пользователей или лишить систему последнего активного администратора.
Другой администратор может изменять аккаунт с логином admin по тем же правилам,
что и любой другой аккаунт. Отдельной суперроли нет.

Manager («Руководитель»):
- дашборд, статистика, заявки, маршруты, обращения, история клиента;
- создание/редактирование/отработка/отмена/возврат заявок, назначение водителей;
- НЕТ удаления заявок;
- существующие города: телефон, тексты, SEO, локальные условия и промо;
- НЕТ создания городов, смены названия/склонения/slug/сортировки/активности города;
- цены города и главной страницы видимы, но только для чтения;
- НЕТ смены нижней/верхней/базовой цены и режима «вывоз/самопривоз»;
- главная: тексты, SEO, контакты, окно выбора города и промо;
- цели: изменение только двух плановых показателей существующей цели;
- НЕТ создания новой цели, смены факта, ручной добавки, даты начала,
  активности цели и настроек автоматической прибавки;
- НЕТ списка чужих аккаунтов, создания пользователей, смены чужих ролей,
  отключения пользователей и сброса чужих паролей;
- свой профиль: просмотр, изменение имени и смена пароля.

Driver — прежний интерфейс обработки заявок. Административная панель не открывается.
Возврат уже отработанной заявки в работу, как и раньше по интерфейсу, доступен
только Admin/Manager; проверка дополнительно выполняется в сервисе.

Границы по целям выбраны по последнему предложению обсуждения: руководитель меняет
план, но не факт/добавку. Расширение этих прав лучше делать отдельно и явно.

## Серверные проверки

SitePermissions перечитывает учётку по идентификатору/метке безопасности серверной
сессии, проверяет активность и совпадение актуальной роли с ролью сессии.
Неизвестная роль больше не превращается в Admin.
Каждая операция изменения дополнительно проверяет права на сервере.

Для руководителя сохранение главной и городов использует разрешённый набор полей.
Редактор города берёт актуальную запись из БД; Update всей сущности для руководителя
не вызывается, чтобы даже при параллельной смене цены администратором не перезаписать
защищённые поля старым значением. План цели сохраняется отдельным ExecuteUpdate
только двух плановых колонок, не затрагивая параллельные начисления факта.

## Статистика

Отдельная вкладка показывает:
- заявки, нажатия на телефон, отработанные заявки и выплаты;
- карточки по городам, включая нулевые;
- период (до 366 дней), город, статус заявки и источник «с сайта/вручную»;
- быстрые периоды: сегодня, вчера, 7 и 30 дней.

Период и город относятся ко всем метрикам, статус/источник — только к заявкам.
Отчётный период — по Минску. Клики хранятся в UTC; границы запросов к старой таблице
заявок переводятся в серверное локальное время, в котором уже хранятся DateCreate.
Это предполагает сохранение часового пояса сервера, использовавшегося при записи истории.

«Отработано» и выплаты считаются по текущему состоянию заявок, созданных в выбранном
периоде. Это не отдельный финансовый отчёт по дате выплаты.
Нажатия на номер не называются фактическими звонками. Подсчёта уникальных людей нет.

Статистика посещений/уникальных хостов, просмотров и UTM/referrer в этом патче
НЕ реализована: её правила мы ещё обсуждаем. Не добавляются вымышленные показатели.
На дашборде остаётся короткий обзор и состояние очереди писем; подробные клики
больше не занимают рабочий дашборд. Старый AdminContactStats оставлен в проекте
для совместимости, но дашбордом больше не используется.

## Проверка после установки

- Создайте двух администраторов с разными логинами. У обоих должна быть кнопка
  удаления и рабочее удаление тестовой заявки, не только у admin.
- Руководитель входит в панель; видит Статистику и Настройки, но не чужих пользователей.
- Руководитель сохраняет текст/телефон города и главной, при этом цены/режим не меняются.
- Пока руководитель держит форму города открытой, администратор меняет цену:
  последующее сохранение текста руководителем не должно вернуть прежнюю цену.
- Под руководителем поля структуры города, цен, факта/добавки целей недоступны.
- Изменение плана руководителем не меняет фактические показатели и настройки автодобавки.
- Руководитель не может удалить заявку или изменить чужую роль/пароль.
- Под администратором доступны три роли в создании/редактировании пользователя.
- Значок смены роли открывает редактор с тремя ролями, без бинарного переключателя.
- Смена роли/отключение завершает старую сессию; проверьте старую открытую вкладку.
- Из профиля руководителя можно изменить только своё имя и собственный пароль.
- На мобильном нет горизонтальной прокрутки меню настроек и карточек статистики.
- Создание обычной публичной заявки, защита повторов, очередь писем и учёт кликов
  должны продолжить работать: их таблицы/сборщики этим патчем не заменялись.
