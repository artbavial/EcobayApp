# Ecobay: надёжные заявки, история клиента и статистика нажатий на звонок

## Установка

Это последовательный ZIP-патч поверх ранее установленных патчей мобильного меню,
страницы пользователей, мобильных карточек и удаления заявок только учёткой admin.
Не разворачивайте его на исходный ecobay.zip без предыдущих патчей:
AdminRequests использует CanDeleteRequestsAsync из уже обновлённого AdminAuthService.
Настройки подключения, SMTP, файлы ключей и пользовательские загрузки в патч не входят.

1. Сделайте резервную копию БД и текущих файлов приложения.
2. Остановите приложение/пул IIS на время обновления. Замените файлы из ZIP с сохранением путей.
3. Выполните `dotnet build` в своей среде. В среде подготовки ZIP .NET SDK и SQL Server отсутствуют,
   поэтому сборка и интеграционные тесты на реальной БД не выполнялись.
4. Примените обновление БД одним из двух способов:
   - `dotnet ef database update 20261027171900_AddRequestReliabilityAndPhoneClicks`
   - либо выполните SQL-скрипт из папки Sql в целевой существующей БД.
   Скрипт создаёт те же таблицы и записывает эту же миграцию в __EFMigrationsHistory.
   Не создавайте дополнительную миграцию на эти же таблицы.
5. Опубликуйте/запустите обновлённое приложение и выполните проверки ниже.

Новые таблицы: RequestSubmissions, RequestEmailOutbox, PhoneClicks.
Существующие заявки не изменяются и не объединяются. Старые дубли клиентов не удаляются.
Связи новых таблиц с Requests/City намеренно не имеют внешних ключей: ранее разрешённое
удаление заявки главным администратором остаётся работоспособным, чеки повторной отправки сохраняются.

## Отправка заявки

- Новый короткоживущий DbContext на операцию.
- Клиент, заявка, чек отправки, задание письма и изменение счётчиков — одна транзакция.
- По GUID отправки повтор после потери ответа возвращает прежний номер заявки.
- Между вкладками и процессами сервера используется SQL Server sp_getapplock по нормализованному телефону.
- Полностью одинаковые нормализованный телефон, имя, описание и страница города за 2 минуты
  считаются техническим повтором, даже если GUID другой. Регистр имени/описания сохраняется,
  обрезаются только крайние пробелы. При другом содержимом/городе или позднее этого окна
  обращение создаётся отдельно. Это не пожизненный запрет заявок с одного номера.
- При повторе клиент и счётчики не создаются/не увеличиваются повторно, второе письмо не ставится в очередь.
- Ответ формы: номер принятой заявки. SMTP больше не задерживает этот ответ.
- Если ответ потерялся, при повторе в той же форме сохраняется GUID; при полной перезагрузке
  работает двухминутная защита одинакового содержимого. После этого окна автоматическая
  дедупликация новой вкладки не гарантируется.
- Публичная форма не раскрывает историю клиента и не перезаписывает имя/заметки существующего клиента.

## Письма

- Фоновый обработчик проверяет очередь примерно раз в 10 секунд.
- У задания есть аренда записи для работы нескольких экземпляров приложения.
- При ошибке повторы через 2, 4, 8, 16, 32 и далее 60 минут.
- На дашборде видны общее количество неотправленных заданий и задания с ошибкой.
- Отправка имеет семантику at-least-once: если SMTP принял письмо, а процесс завершился
  до записи SentAtUtc, повтор письма возможен. Защита от второй заявки при этом сохраняется.
- Если заявка удалена до отправки, уведомление пропускается.
- Для своевременной работы фоновых задач настройте постоянную работу приложения/пула IIS
  (AlwaysRunning/предзагрузка при поддержке хостинга). Пока приложение остановлено, писем не будет;
  задания переживают перезапуск и продолжают обработку после старта.
- Временные метки очереди хранятся в UTC. Время старой модели Requests сохраняет текущую
  серверную локальную конвенцию, чтобы не сдвигать существующие отчёты.

## История клиента

- В списке заявок рядом с телефоном есть значок истории (только для администратора).
- История также показывается при создании/редактировании и в подробностях заявки.
- Номер в ручной форме проверяется после изменения поля/потери фокуса; при распознавании
  номера со скриншота история обновляется при перерисовке формы.
- История объединяет обращения по полному нормализованному номеру, в том числе если в старой
  базе несколько клиентов с разным форматированием одного номера. Поддерживаются +375, 375,
  80 и местный девятизначный формат, пробелы, дефисы, скобки и точки.
- Не используется совпадение только последних девяти цифр международных номеров.
- Видны общее количество, количество необработанных и последние 30 обращений.
- Если есть необработанные, новое ручное обращение создаётся только после подтверждения оператора.
- Нажатие на сам телефон остаётся звонком; история открывается отдельным значком.

## Нажатия на звонок

- Блок на дашборде под верхними KPI: итог за сегодня + все активные города, включая нулевые.
- Отдельная строка общей страницы/контактов: город не угадывается по IP или прошлому выбору.
- Город определяется по странице, с которой нажали tel:-ссылку, а не фактическому месту жительства посетителя.
- Считаются публичные tel:-ссылки. Админка и страница водителя исключены.
- Событие отправляется неблокирующим fetch keepalive: открытие набора номера не ждёт сети.
- События с одним GUID считаются один раз; отдельные повторные клики учитываются отдельно.
- Отчётный день — 00:00–24:00 по Минску (UTC+03), события в БД — UTC.
- Исторические клики до установки восстановить нельзя. IP и телефон посетителя в PhoneClicks не сохраняются.
- Это не число разговоров и не уникальные люди. Сетевые сбои/блокировщики могут приводить к недоучёту;
  публичный счётчик не является защищённой от всех ботов системой биллинга.
- На endpoint включён лимит 120 событий в минуту на IP и базовая проверка Origin/Sec-Fetch-Site.
  При reverse proxy убедитесь, что приложение получает корректный RemoteIpAddress;
  без настройки доверенных прокси лимит может оказаться общим для всех посетителей.
- Для обновления используйте кнопку обновления блока либо общего дашборда.

## Обязательный приёмочный прогон на тестовой копии БД

1. Одна обычная отправка: один клиент (или найденный старый), одна заявка,
   один чек, одно задание письма; форма сразу показывает номер.
2. Два быстрых нажатия в форме: один номер заявки, нет второго увеличения счётчиков.
3. Две вкладки с одинаковыми полями одного номера одновременно: одна заявка,
   два чека с разными GUID допускаются, одно задание письма.
4. Одинаковые последние 9 цифр, но разные полные международные номера:
   разные клиенты, не объединяются.
5. Другое описание/город — отдельная допустимая заявка; одинаковая через 2 минуты
   с новым GUID — тоже отдельная. Не тестировать точную границу окна без учёта серверного времени.
6. Сделать SMTP недоступным: заявка видна в панели, форма успешна,
   очередь помечена ошибкой, восстановление SMTP приводит к доставке при повторе.
7. Перезапустить приложение с ожидающими письмами — очередь не теряется.
8. Номер с открытой заявкой в ручной форме: предупреждение, отказ подтверждения
   ничего не создаёт, подтверждение создаёт отдельное обращение.
9. История с телефона: вертикальная разметка без горизонтальной прокрутки.
10. Нажать телефон на /gomel и на общей странице: +1 в соответствующих строках.
    Звонок из админки/водителя не меняет статистику публичных кликов.
11. Проверить границу суток по Минску, города с нулевыми значениями и обновление блока.
12. Под обычным администратором удаления нет; под admin удаление работает и не блокируется
    новыми таблицами. Мобильное меню и окна пользователей остаются прежними.

## Эксплуатация

Очередь и журнал кликов сохраняются в БД; по мере роста стоит утвердить срок хранения
и отдельное задание очистки/агрегации. Автоматическая очистка в этом патче не включена,
чтобы не удалять историю без согласованного срока хранения.
