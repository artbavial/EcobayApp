# Ecobay: патч v2

## Какую версию обновляет

Патч рассчитан на предыдущий архив **Ecobay_updated.zip**, выданный в этой переписке. Это не полный проект и не готовая папка публикации IIS. Если после того архива вы правили те же файлы самостоятельно, сначала объедините изменения через Git или сравнение файлов, не заменяйте их вслепую.

В ZIP включены только новые и изменённые файлы с исходными путями. Картинок, зависимостей, `bin`, `obj`, файлов конфигурации с паролями и тестовой базы в нём нет. `Ecobay-v2.patch` содержит те же изменения в формате unified diff; это альтернативный способ установки, применять оба способа не нужно. `patch-manifest.json` перечисляет файлы и SHA-256 предыдущей и новой версий.

## Установка

1. Сделайте резервную копию исходников и БД. Не подменяйте исходники работающего приложения до подготовки миграции и публикации.
2. Распакуйте ZIP в корень предыдущего проекта с сохранением путей и заменой перечисленных файлов. Либо из корня проекта выполните:

   ```sh
   git apply --check Ecobay-v2.patch
   git apply Ecobay-v2.patch
   ```

3. Примените **одним** из способов новую миграцию `AddCityLocalContentAndRequestIndex`:

   ```sh
   dotnet ef database update
   ```

   Или выполните `Sql/2026-10-25_PatchV2.sql` на вашей SQL Server БД. SQL-скрипт рассчитан на БД с уже установленной первой версией и её миграцией `AddCityActiveMainPageAdminAuth`; скрипт идемпотентный.

4. Соберите и опубликуйте проект обычным для вашего IIS/хостинга способом. `appsettings.json`, пароли и каталог ключей `App_Data/keys` оставьте своими; этот патч их не меняет.

Миграция добавляет четыре nullable-поля `PageCities` и индекс заявок по дате/ID. Таблицы и заявки не удаляются, начальные/фактические значения целей не меняются. Только старые стандартные H1, Title и description общей страницы с обещанием работы по всей Беларуси заменяются на корректную географию; произвольные тексты, введённые вами, не перезаписываются. Проверьте собственные рекламные формулировки в разделе «Главная сайта».

## Изменения

### Главная и страницы городов

- Телефон крупной кнопкой с иконкой звонка расположен **до** декоративных иконок и списка городов. На мобильном кнопка на всю ширину.
- Указано: работаем **только** в активных городах из БД и населённых пунктах районов этих городов. На других территориях вывоз не обещается.
- В воскресенье принимаем заявки, но не собираем и не вывозим технику. Информация приведена к одному виду в главной, FAQ и контактах.
- Юридическое название в контактах исправлено на **ООО «ЭКОТЕХБЕЛК»**; на остальных страницах оно уже было таким.
- Кнопка запуска видео с вращающейся надписью центрирована. Текст по окружности переведён на SVG, не зависит от вычислений CircleType и ширины контейнера.
- На страницах городов появились необязательные местные блоки. Их заполнение описано в `CITY_PAGES.md`. Пустые блоки не отображаются, HTML из полей не исполняется.

### Дашборд

- Заявки за сегодня, последние 7 и 30 дней, общее количество.
- Изменение за 7/30 дней относительно предыдущего такого же периода, в штуках и процентах. При нулевом предыдущем значении процент не выдумывается.
- Цели: факт / план по клиентам и технике, процент выполнения и ручная добавка.
- Кольцевая диаграмма заявок по городам за последние 30 дней, рядом точные количества и доли. Рисуется средствами CSS без новой внешней библиотеки.
- Последние 8 заявок за сегодня. «Смотреть больше» открывает вкладку «Заявки» с фильтром на сегодняшний день.

Статистика строится по реальным строкам `Requests`, а не по ручной корректировке целей. Записи без определяемого города учитываются отдельной группой. Сравниваются календарные периоды, текущий день включён и пока не завершён. Используется существующая в проекте договорённость `DateCreate = DateTime.Now`: границы суток соответствуют часовому поясу сервера. Для белорусского рабочего дня проверьте часовой пояс сервера/IIS; исторические даты этим патчем не сдвигаются.

### Заявки

- Отдельная вкладка с фильтром дат, города, имени или телефона.
- Максимум **30 дней включительно**: например, 1–30 октября можно, 1–31 октября нельзя. Конечная дата включается целиком.
- Страницы по **20, 30 или 50** записей, «Назад»/«Далее», количество результатов.
- Фильтрация и пагинация выполняются в БД. Порядок: новые сверху, при совпадении даты сортировка по ID.
- Удаление заявки сохранено с подтверждением. Оно не уменьшает цели автоматически, как и в предыдущей версии.

### Цели

Во вкладке «Цели» выбирается год и редактируются существующие поля:

- `TargetClients`, `TargetItems`: целевые значения;
- `ActualClients`, `ActualItems`: фактические значения;
- `InactiveRequests`: **ручная добавка** к прогрессу клиентов;
- `StartDate`, `IsActive`.

Формула сохранена:

```text
Прогресс клиентов = (ActualClients + InactiveRequests) / TargetClients × 100%
Прогресс техники = ActualItems / TargetItems × 100%
```

`InactiveRequests` не является процентом: например, факт 123 + добавка 17 при цели 250 дают 56%. Полоса ограничена 100%, а в панели фактический процент может быть выше. Ручная добавка не создаёт заявки и не влияет на диаграмму/сравнение периодов.

Добавлена защита от перезаписи свежих данных: если во время редактирования пришла заявка или другой администратор изменил цель, сохранение попросит сначала загрузить актуальное состояние. Открытие главной страницы больше не создаёт новую активную цель взамен отключённой.

На сайте счётчики в блоке целей теперь показывают выполненное количество и целевое значение, а не выдают план за факт. Изменения видны при новом открытии/обновлении публичной страницы.

## Что проверено

- Сборка проекта .NET 8 без ошибок.
- Один короткий браузерный smoke-тест на изолированной SQLite БД с искусственными данными: статистика дашборда, диаграмма, 8 строк за сегодня, переход к заявкам, пагинация, размер 50, ограничение дат, сохранение InactiveRequests, сохранение и вывод городского текста.
- Положение телефона до иконок, центр кнопки видео и отсутствие горизонтального переполнения на ширине 390 px.
- В этом прогоне ошибок JavaScript не обнаружено.

Боевая БД, хостинг и Google Ads не проверялись и не изменялись. Полного регрессионного тестирования не было, в соответствии с запросом на минимальные проверки. SQL Server миграция сгенерирована, но на вашем сервере ещё не применена.

Сборка также показывает предупреждение о старой версии MailKit 4.14.1; пакет существовал в исходном проекте и этим патчем не обновлялся. Обновление зависимости лучше сделать отдельным небольшим изменением с проверкой отправки почты.
