# Ecobay: модальные заявки, фактический вес и отметка звонка

Единый ZIP-патч поверх установленной версии с аналитикой, OCR и компактными городами CMS v0.9.4. Предыдущие роли, меню, статистика посещений, распознавание телефонов и расположение уведомлений сохранены.

## Установка

1. Сделайте резервную копию БД и текущего приложения.
2. На время установки остановите приложение / пул IIS.
3. Распакуйте ZIP в корень исходников с заменой. Это патч, не полный проект.
4. Примените обновление БД одним способом:

```bash
dotnet ef database update 20261027211554_AddRequestWeightAndCalls
```

Альтернатива: выполнить `Sql/2026-10-28_RequestWeightAndCalls.sql` в нужной БД через SSMS. Скрипт содержит `GO`, предполагает уже установленную миграцию аналитики `20261027191939_AddSiteAnalytics` и регистрирует новую миграцию в `__EFMigrationsHistory`. Не запускайте оба способа параллельно.

5. Пересоберите и опубликуйте приложение обычным способом, затем запустите его. Не копируйте C#/Razor в publish-каталог вместо повторной публикации.
6. Проверьте создание/изменение заявки, отработку с весом, отметку/отмену звонка и раздел статистики.

Миграция добавляет nullable-поля к заявке, nullable-вес к истории отработки, таблицу истории отметок звонка и индексы. Старые данные не переписываются. Имя миграции содержит дату UTC 27 октября; патч подготовлен 28 октября по Минску. Откат Down удаляет добавленные данные: без отдельного решения и резервной копии его не запускайте.

## Модальные окна

- На дашборде основная кнопка «Обновить» заменена на «Новая заявка».
- Создание и изменение на дашборде и в списке заявок открываются поверх текущего экрана; переходить к форме вверху страницы больше не нужно.
- Редактирование из подробностей маршрутной заявки также использует это окно.
- Отработка, отмена и возврат в работу открываются в модальном окне с проверками рядом с полями.
- Фон заблокирован, фокус остаётся в диалоге, Escape закрывает его, если не идёт сохранение. Нажатие на затемнённый фон не закрывает несохранённую форму.
- На телефоне окно прокручивается внутри, кнопки не требуют прокрутки всей страницы вверх. Высота учитывает доступный visual viewport.
- Дашборд после создания/изменения обновляется сам. Его список на телефоне представлен вертикальными карточками вместо широкой таблицы.

Отдельное предупреждение о несохранённых полях при явном закрытии не добавляется: кнопки «Закрыть», «Отмена» и Escape отменяют редактирование.

## Фактический вес

При новой отработке обязательно указать вес от 0,01 до 1 000 000 кг. Допустима дробная часть, значение хранится с точностью до 0,01 кг. Проверка выполняется на сервере для всех пользователей, которые отрабатывают заявки, в том числе водителей.

Вес записывается в текущую заявку и событие отработки. Он виден в карточке, подробностях, истории клиента и дашборде; в маршрутном списке показывается для отработанных точек.

У старых отработанных заявок вес остаётся неизвестным, а не нулевым. Администратор или руководитель может уточнить вес через изменение отработанной заявки: корректировка записывается в историю. Старую заявку без веса допустимо редактировать, не придумывая вес. Уже известный вес нельзя стереть пустым полем или заменить нулём.

При возврате в работу текущие вес и выплата очищаются; прежний вес остаётся в истории. Новая отработка требует нового веса. Отмена также не оставляет текущий фактический вес.

Вес не подставляется из калькулятора сайта, не меняет автоматически цены и не переводит счётчики целей в килограммы.

## Статистика веса

Новый блок «Вывоз · фактический вес» показывает:

- Известный суммарный вес, кг.
- Средний вес среди заявок с указанным весом.
- Количество отработанных и количество записей без веса.
- График веса по дням с точными дробными значениями.
- Разбивку веса и полноты заполнения по городам.

Основание периода — дата отработки по времени Минска, а не дата поступления. Применяются выбранные город и источник «сайт / вручную». Фильтр статуса в этом блоке не применяется: он всегда показывает текущие отработанные заявки. Если у старой записи отсутствует сама дата отработки, привязать её к периоду нельзя и этот блок её не включает.

Отменённые и возвращённые в работу в сумму не входят. Повторная отработка не суммирует старый и новый результат: учитывается текущее завершение один раз. Уточнение веса меняет результат исходной даты завершения; аудит старых значений сохраняется. Это отчёт о текущем состоянии, не неизменяемый бухгалтерский регистр отгрузок.

Вес относится к городу заявки, а не геолокации. Ограничение выборки: 50 000 отработанных заявок и диапазон до 366 дней; при превышении нужно сузить фильтр.

## Отметка «Звонили»

Кнопка «Отметить звонок» находится у заявки, в том числе в списке водителя, дашборде и подробностях. Её могут использовать действующие пользователи Admin/Manager/Driver; автор берётся из серверной сессии.

Первое нажатие сохраняет серверное время UTC и сотрудника, кнопка становится «Звонили». В интерфейсе время показывается по Минску. Следующее намеренное нажатие снимает отметку. После повторной установки записывается новое время.

Отметка не меняет статус, выплату, вес или дату обработки. Нажатие на ссылку телефона не устанавливает её автоматически. Это заявление оператора о попытке звонка, не подтверждение состоявшегося разговора, его длительности или результата.

Установка и отмена остаются в истории заявки с автором и временем. При отмене также сохраняется время снятой отметки. Если запись уже изменил другой сотрудник, устаревшее действие отклоняется и данные обновляются: случайный повтор не должен отменять чужую свежую отметку.

Одновременные серверные операции изменения статуса и звонка используют SQL Server application lock по ID заявки. Удаление заявки по прежним правам удаляет и зависимую историю звонков в той же операции каскадом.

## Минимальные проверки

Сборка .NET 8 и синтаксис JS проверены. На временной SQLite проверены обязательность веса, запись результата, установка/отмена звонка, защита от устаревшего повторения, неизменность статуса/выплаты/веса при отметке, история, повторная отработка без двойного счёта и каскадное удаление истории.

В SQLite SQL Server application locks заменялись тестовым перехватчиком. Это проверка логики, а не проверка SQL Server или реальной конкурентной нагрузки. На рабочей БД миграция не выполнялась.

Адаптивная компоновка и поведение нативного диалога проверены в Chromium с синтетическими данными. Полная отправка формы со скриншотом и работа на устройстве пользователя не проверялись. Предыдущий OCR-код не менялся.

Сохраняется исходное предупреждение NU1902 по MailKit 4.14.1; обновление почтовой библиотеки не входит в этот патч. Адрес предупреждения: https://github.com/advisories/GHSA-9j88-vvj5-vhgr .
